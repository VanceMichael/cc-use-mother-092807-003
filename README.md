# 森林景观恢复承诺与社区收益核证

跟踪森林景观恢复地块、权利、监测、灾害、资金与社区收益，回答每一笔恢复资金
**对应哪块土地、哪些证据、哪些社区权益**。

## 参与方与事实

主要参与方包括景观恢复计划秘书处、地方社区和土地权利人、实施机构、生态监测
团队、出资与审核人员。领域资料记录以下已经确认的事实：

- 全球有超过4.6亿公顷森林处于退化状态
- 91个国家和地区承诺恢复超过1.9亿公顷森林
- 报告强调当地民众参与、权利保障和长期融资

## 服务结构

领域资料（`contracts/`、`fixtures/`、`src/news_context_003.py`）描述领域边界；
完整的承诺与核证服务位于 `src/restoration/`：

| 模块 | 职责 |
| --- | --- |
| `storage.py` | SQLite 持久化：地块、权利人、基线、方案、协商、批次、样方、协议、观测、估算、灾害、资金、里程碑、持久任务、只增审计日志 |
| `geometry.py` | GeoJSON 多边形面积与空间重叠判定（无外部依赖） |
| `auth.py` | 六类岗位、权限矩阵、敏感资料访问控制、审计留痕 |
| `parcels.py` | 项目/地块申报、空间重叠与用途冲突检查、权利人、退化基线、恢复方案、社区协商与申诉 |
| `monitoring.py` | 监测样方、采集方法协议、幂等观测、异文复核、碳与生计估算及确认冻结 |
| `work.py` | 作业批次、火灾/病虫害等灾害、补植与重做（历史投入与失败原因保留） |
| `funding.py` | 资金来源与分配、付款里程碑、职责分离、暂停/扣留、社区收益、资金证据链追溯 |
| `tasks.py` / `service.py` | 持久任务队列（到期监测、待协商申诉、暂停资金）与重启恢复、服务门面 |

岗位（role）：

- `secretariat` 秘书处；`community_liaison` 社区联络人；`implementer` 实施机构；
  `monitor` 生态监测团队；`finance` 出资与核款人员；`auditor` 审核人员（只读全量追溯）。

## 核心不变量

- **防重复计算**：地块申报时对全部在效地块做空间重叠检查；同用途重叠按
  “重复申报”拒绝，互斥用途（如保护林/水源保护区与采矿、工业农业）按用途冲突拒绝，
  冲突明细返回既有地块与所属项目。同一项目同一外部编号重复申报幂等。
- **采集方法与适用季节冻结**：样方首批观测确定协议后，该时间序列只能继续使用
  同一协议；协议新版本不能改动既有观测；观测季节必须同时在协议与恢复方案声明的季节内。
- **确认结果不可改写**：估算结果（碳、生计指标）确认后冻结；之后的新模型只能
  另存草稿，不能覆盖同一（地块、指标、季节）已确认值。
- **异文数据进复核**：越界或相对退化基线异常跳变的观测进入 `pending_review`，
  复核（且复核人不得是采集人本人）通过前不参与任何估算。
- **重复观测幂等**：以幂等键去重，重放返回同一条观测。
- **受灾不抹账**：灾害可触发补植（replant）或重做（redo）；失败批次保留投入与
  失败原因，新批次以前驱链接回历史，redo 把地块置为 rework。
- **付款职责分离**：提交证据的人不能批准或执行该笔付款；财务岗位无权提交证据；
  证据只能引用已确认估算并关联具体批次；存在未决灾害或申诉时付款被阻塞，
  必须先暂停核查、阻塞解除后才能恢复。
- **敏感资料最小化**：社区敏感权利人信息与协商备注只对社区联络人、秘书处、
  审核岗位开放，其他岗位整表拒绝并写拒绝审计；所有授权/拒绝均进入只增审计日志。
- **重启续跑**：到期监测、待协商申诉、暂停资金任务持久化；服务重启时把崩溃中
  的 `in_progress` 任务复位为 `pending`，条件未满足的任务推后重试，不丢任务。

## 快速使用

```python
from src.restoration import RestorationService, Actor

svc = RestorationService("restoration.db")  # 或 ":memory:"
secretary = Actor("u_sec", "秘书处甲", "secretariat"); svc.ac.register_user(secretary)
# ……登记项目、地块（自动做空间冲突检查）、基线、方案、协商、样方、观测、
# 估算确认、作业批次、资金来源、付款里程碑；最后：
trace = svc.funding.trace_payment(auditor, milestone_id)
# trace 含土地、资金来源、证据（估算+观测依据+批次链含失败历史）、
# 社区权益（权利人/协商/收益）与灾害事件
```

`FundingService.trace_payment` 返回的证据链示例结构见 `docs/payment-trace.example.json`。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读写仓库内文件（`:memory:` SQLite），不需要连接外部业务系统。

领域资料本身的校验入口仍为 `src/news_context_003.py`，结构见
`contracts/context.schema.json`，不含真实身份信息的示例见 `fixtures/context.json`。
