# 承诺与核证服务设计

`src/restoration_service.py` 在领域资料（`src/news_context_003.py`）之上提供可执行的承诺与核证流程，覆盖地块、权利、承诺、监测、灾害、资金和社区收益。

## 数据边界

- **地块与权利**：边界（简单多边形）、权利人、退化基线；权利人的敏感资料仅授权岗位可读。
- **恢复承诺**：恢复方案、土地用途、资金来源；申报时检查空间重叠与用途冲突。
- **监测核证**：样方在登记时冻结采集方法与适用季节；观测以（样方, 幂等键）标识。
- **灾害与补植**：灾害事件自动暂停相关付款；补植或重做保留历史投入与失败原因。
- **资金与收益**：付款里程碑绑定监测证据要求，按阶段放行。

## 关键不变量

1. 同一地块不会被两个生效承诺同时计算：与生效承诺空间重叠的申报一律拒绝，用途相同记为重复申报，用途不同记为用途冲突；仅共边或共点不算重叠。
2. 监测数据只能按冻结的采集方法与适用季节提交；重复提交幂等返回原记录，异文数据进入复核案件，原记录保持不动。
3. 已确认的观测结果不可改写：复核只能保留原数据，估算模型的产出单独存放，永远不能覆盖确认值。
4. 付款放行必须同时满足：确认观测数量达到证据要求、至少两名不同的出资审核岗位批准、全部审批人与该承诺的监测提交人无关。提交监测的人不能独自批准付款。
5. 社区敏感资料（权利人细节、协商纪要）仅向授权岗位开放；审计视图按调用者岗位脱敏。
6. 受灾地块的历史作业批次与失败原因永久保留；资金任务只有在相关灾害完成补植或重做后才能恢复。
7. 服务状态可整体快照，重启恢复后到期监测、待协商申诉和暂停资金任务保持连续，快照往返内容稳定。

## 岗位与权限

| 岗位 | 职责 |
| --- | --- |
| 秘书处 | 登记地块与样方、受理申报、设立里程碑、安排补植、恢复资金任务 |
| 社区联络 | 开启协商、处理申诉（可读取社区敏感资料） |
| 实施机构 | 登记作业批次、完成补植或重做 |
| 生态监测团队 | 提交观测与估算、报告灾害 |
| 出资与审核人员 | 批准并放行付款（不能批准自己提交监测的项目） |
| 独立审核 | 确认观测、复核异文、审计解释（可读取社区敏感资料） |
