# 领域边界

跟踪森林景观恢复地块、权利、监测、灾害、资金与社区收益，使每一笔恢复资金都能
解释清楚对应哪块土地、哪些证据、哪些社区权益。

现有领域资料围绕以下边界组织：

- 地块和权利基线
- 恢复承诺
- 监测核证
- 灾害与补植
- 资金和社区收益

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号
或凭据。

# 服务不变量（`src/restoration/` 实现）

## 1. 地块与权利基线

- 地块登记 GeoJSON 边界、外部编号、土地用途与面积；边界登记后不就地删改，
  补植与重做通过作业批次留痕。
- 权利人记录权属类型（习惯/共有/租赁/国有/私有/共有共管）与权属文书；
  标记为敏感的资料仅向社区联络人、秘书处、审核岗位开放。
- 退化基线记录测量日期、郁闭度、土壤指标、退化等级与证据。
- 恢复方案记录恢复途径、目标郁闭度、树种、**适用监测季节**与实施年限。

## 2. 恢复承诺与防重复计算

- 申报地块必须与全部在效地块（registered/active/rework）做空间重叠检查：
  - 同用途重叠 → `duplicate_claim`，按重复申报拒绝；
  - 互斥用途重叠（保护林/水源涵养区/共有林/恢复区 对 采矿、工业农业等）
    → `incompatible_use`，按用途冲突拒绝；
  - 其它重叠 → `spatial_overlap`；拒绝信息附既有地块、所属项目与用途。
- 仅边相接、无实质面积交集（默认 ≥1 平方米）不算重叠。
- 同一项目同一外部编号重复申报幂等返回既有地块。

## 3. 监测核证

- 样方首批观测确定采集方法协议后，协议在该样方时间序列上冻结；新协议版本
  不得改动既有观测或顶替样方方法，只能另建样方。
- 观测季节必须同时落在协议与恢复方案声明的适用季节内。
- 观测携带幂等键：同键重放返回原记录，不产生重复数据。
- 越界值、相对退化基线异常跳变值进入 `pending_review`；复核人不得是采集人
  本人；复核采纳前该观测不得作为估算依据。
- 估算（碳、生计指标）基于已采纳观测；`confirmed` 结果不可删除、不可更新、
  不可被后续模型版本改写；同指标同季节已存在确认结果时，新模型提交即拒绝。

## 4. 灾害与补植

- 灾害事件记录类型（火灾、病虫害、干旱、洪水、风倒）、时间、受灾面积、
  严重度与原因，可关联受影响批次。
- 响应为 replant/redo/accepted_loss，且只能响应一次。
- replant/redo 将受影响批次置为 failed 并永久保留其投入金额与失败原因；
  新建批次以 `predecessor_batch_id` 链接历史；redo 同时把地块置为 rework。

## 5. 资金与社区收益

- 资金来源记录出资方、币种与承诺总额；地块分配累计不得超过承诺额。
- 付款里程碑按阶段（动员、定植、期中核证、最终核证、收益分成）推进：
  pending → evidence_submitted → approved → paid，可 suspended/withheld。
- 付款证据只能引用本地块的**已确认**估算并关联具体作业批次。
- 职责分离：财务岗位无权提交证据；提交证据的人不能批准、不能执行同一笔付款；
  复核人不能是观测采集人。
- 存在未响应灾害或未决申诉时批准被阻塞；须先暂停（suspended），阻塞解除后
  恢复到暂停前阶段；也可扣留（withheld）。
- 社区收益记录现金转移、岗位、基建、培训、权属支持或实物，及受益人数。
- `trace_payment` 输出完整证据链：地块与项目、资金来源、估算与其观测依据、
  沿前驱回溯的批次链（含失败原因与历史投入）、权利人、协商结论、社区收益、
  灾害事件，以及提交/批准/付款的人员与时间。

## 6. 持久任务与重启恢复

- 三类任务：due_monitoring、grievance_consultation、payment_suspension；
  按 (kind, ref_key) 去重，重复入队不产生新任务。
- 任务与状态持久化在 SQLite；服务重启时把 in_progress 复位为 pending。
- 条件未满足（无采纳观测、申诉未结案、阻塞仍在）的任务推后重试而非误标完成。

## 7. 审计

- 每次权限校验（允许或拒绝）写只增审计日志：时间、人员、岗位、动作、
  对象、结果与详情；审核岗位可只读检索。
